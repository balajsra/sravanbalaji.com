After trying [Vim](https://www.vim.org/), [Emacs](https://www.gnu.org/software/emacs/) ([Doom Emacs](https://doomemacs.org/) specifically), [Zed](https://zed.dev/), [Atom](https://atom-editor.cc/), and [CLion](https://www.jetbrains.com/clion/), I have found myself coming right back to [Visual Studio Code](https://code.visualstudio.com/). While I love the insane customizeability and keyboard-driven philosophy of Vim and Emacs, they take way too much effort to maintain and get up and running for new tech stacks / languages. Atom and Zed are similar enough to VSCode that I can't really see a reason why you should use them considering VSCode's huge advantage in community support (i.e., [extensions](https://marketplace.visualstudio.com/vscode?hl=en-US)).

I did use Emacs for a couple years and loved [Org Mode](https://orgmode.org) and [Magit](https://magit.vc), but I found they were too tied into the editor for my liking. Using org mode outside of emacs just isn't worth it. I'm the type of person to constantly experiment with the tools I use, so I don't like being tied down to one particular text editor forever.

CLion is great if you're developing large and complicated C/C++ projects, but VSCode's [remote development](https://code.visualstudio.com/docs/remote/remote-overview) and [devcontainer](https://code.visualstudio.com/docs/devcontainers/containers) support are so far ahead that I can't justify using anything else. You can also replicate a lot of CLion's features in VSCode using things like [CMake Tools](https://marketplace.visualstudio.com/items?itemName=ms-vscode.cmake-tools) and [clangd](https://marketplace.visualstudio.com/items?itemName=llvm-vs-code-extensions.vscode-clangd).
